Esforço no plano

A FALÁCIA DA ECONOMIA DE TOKEN

Bom, bonito e barato não coexistem sem método

Economizar token sem método

  • Plano raso, ambiguidade sobra para a execução
  • Retrabalho, bug em produção, ocorrência de suporte
  • O barato de agora vira o caro de depois

Token investido em planejamento

  • Ambiguidade eliminada antes de escrever código
  • Menos ciclo de correção, menos ocorrência aberta
  • O caro de agora evita o caro maior de depois

CUSTO × RESULTADO

Quem garante a saída é o método, não o modelo

Se fosse a IA que garantisse

  • Qualidade depende de trocar para o modelo mais caro
  • Cada harness novo reabre a mesma dúvida
  • Nenhum jeito barato de manter o mesmo padrão

Como o método garante

  • Hooks, portões e agentes read-only, não o tamanho do modelo
  • Mesmo contrato roda com LLM mais barato — GLM, MiniMax, outros
  • Token a mais compra planejamento — a fonte do retrabalho caro

BUILD E RUN

Mesmo método, gatilho diferente

sprintx · Build

  • Cinco estágios, E1 a E5
  • Saída: ocorrência encerrada, com dois relatórios

GARANTIAS

Três camadas, cada uma cobre o que a anterior não garante

HOOKS

Aviso → bloqueio

AGENTES

Só leitura

SEGURANÇA

Falha fechada

Hook de segredo nasce em bloqueio. Falso positivo ali é raro; segredo commitado não tem volta.
